# Concurrent edits (ticket 17 — extend, don't rewrite)

Implementation notes, moved from the root `CLAUDE.md` on 2026-10-18 (read on demand; the
index is [README.md](README.md)). Extend them with the code they describe.

- **Files:** `crates/diff/src/contain.rs` (the pure check), `crates/store/src/concurrent.rs` (`check_head_changes(base_md, head_md, local_md, base_manifest, head_manifest, local_manifest) -> HeadChanges {hunks, assets}` — what CLI and server both run; `HeadMovedError {name, base, head, by, reason: Unchecked | Missing | MovedAgain{checked}}` = `StoreError::HeadMoved`), `crates/sidecar/src/binding.rs` (conflicted Sidecars), `cli/push.rs` (the step + `head_moved_error`), `store/src/docs.rs::push_version`, ADR `docs/adr/0002-concurrent-edits-by-content.md`. No migration.
- **The check** (`annotary_diff::contains_changes(base, head, local) -> Contained | Missing{hunks}`): histogram line diffs base→head and base→local grouped into chunks of overlapping changes (intersecting, or an insertion / deletion touching an edit); a chunk the head changed is contained when local's text for it equals the head's, or both only inserted there and the head's insertion is a run inside local's; both changed differently ⇒ the same at UAX #29 word-token level. Repeated under a few valid alignments (`Align`: histogram / minimal Myers × split-early none / new side / replaced side × slide up / down) — contained when any shows it; each alignment is sound, so retries only remove false refusals. Never add an unsound shortcut (a "head → local" heuristic was tried and accepted files that lacked a deleted duplicate line). `local == base` short-circuits to missing. Hunks: base→head, ≤ `CONTEXT` (3) lines of context that never reach into another head change, `@@ -b,n +h,m @@`. Assets (`missing_asset_changes`): every `ref` whose `(ref, hash)` differs base→head must have the head's entry in local; other refs are free.
- **Wire / store:** commit `contains_head: N` (the head the CLI checked) and `discard_head_changes: bool`; `strict` is no longer read. `push_version`: `already` first (identical to head ⇒ no check); then with `base_version < head`: discard ⇒ accept, `discarded = base+1..=head` (`PushOutcome.discarded`, response `discarded[]`, `version.pushed` payload `discarded`); `contains_head == head` ⇒ accept, rechecked with `check_head_changes` over the three blobs while `Store::verify_edge()` (else `Missing`); `contains_head ≠ head` ⇒ `MovedAgain` ("head moved again (now vN)"); neither ⇒ `Unchecked` (older CLIs). All 409 `head_moved` → exit 5, `base` / `head` / `by` in the body. `head_moved` in the response = what an accepted push was over.
- **CLI:** `push` with a target, `base_version < head` and identity ≠ head: `GET …/versions` (authors of base+1..=head, both md hashes + manifests) → both blobs → `check_head_changes`. Missing ⇒ `error: v5 by @x changed FILE since your v4 — those changes are not in your file — put them into FILE and push again` + the unified diff + `asset REF changed|added|removed in vN` as detail lines (text), or `{error: "head_moved", message, hint, base, head, by, missing[{hunk, lines}], assets[{ref, change}]}` (`--json`; detail lines are *not* folded into `hint`). Several Versions ⇒ `v5–v7 by @a, @b`. Contained ⇒ `contains_head`, the head text reused by `reanchor_for`, no warning. `--discard-head-changes` ⇒ `warning: discarding v5 by @x since your v4` before the `assets:` line. `--force` keeps its meaning (rebind) and never skips the check. No automatic retry on "moved again". `wait` DETAIL `v6 by @x discarding v5 "msg"`, `--json` field `discarded` (in `all`).
- **Conflicted Sidecar** (`Binding::from_text`): markers `<<<<<<<` / `|||||||` (diff3 base, dropped) / `=======` / `>>>>>>>` at column 0; each side parsed alone (an unparseable side keeps today's error; markers out of order = `ParseError::Invalid`); different `id` ⇒ `ParseError::Conflict{what}` → exit 5 `sidecar_conflict` "NAME.annotary has conflicting Document ids — keep one side"; the same `id` with different `vault` names is a Vault rename between the two pulls (CMD-5): the newer side's (higher `base_version`) `vault` is kept, nothing else from it; `base_version` (+ its hash / name / assets) = the lower side; `actions.available` only when both sides agree (`actions_disagree` ⇒ none sent + a note); `conflicted` ⇒ a note naming the base used. `pull` uses the same Binding (its local-edit rule compares against the lower side's hash). Push and pull write the file clean.
- **Decisions to keep:** Annotary never merges and never writes conflict markers into a `.md`; refusal happens before re-anchoring output and before any upload; overlaps that do not resolve at token level are refused (open question 1 of the ticket); one verify switch for everything the edge computes (`--verify-edge`, alias `--verify-placements`); `--discard-head-changes` is the only overwrite and it is visible in stderr and the event log; Versions stay a single line.
