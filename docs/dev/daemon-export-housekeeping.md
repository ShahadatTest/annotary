# Daemon, export, housekeeping (ticket 13 — extend, don't rewrite)

Implementation notes, moved from the root `CLAUDE.md` on 2026-10-18 (read on demand; the
index is [README.md](README.md)). Extend them with the code they describe.

- **Files:** `cli/daemon.rs` (`DaemonCmd`, `Plist {label, binary, data_dir, port, log}::render/parse/read`, `plist_path()` = `$HOME/Library/LaunchAgents/<label>.plist`, `label()`, `log_path(data)` = `DIR/logs/server.log`, `Status`/`status()`/`running()`, the launchctl wrappers `is_loaded`/`bootstrap`/`bootout`/`kickstart`, `unsupported(os)`), `cli/export.rs`, `crates/store/src/housekeeping.rs`, `crates/store/src/backup.rs`, `server/housekeeping.rs` (route table in its header; `tick`, `ticker`, `Report`, `GC_GRACE`, `DEFAULT_INTERVAL`, `INTERVAL_ENV`).
- **`daemon` (macOS only):** `install [--port]` = (stop an installed agent first) → `Store::open` (a foreground `serve`'s LOCK ⇒ exit 5 before anything is written; first-run setup inline via `cli::serve::first_run` when empty — same prompts/`ANNOTARY_SETUP_*` answers) → drop the store → write the plist → `launchctl bootstrap gui/UID PLIST` + `kickstart` → wait ≤ 15 s for `server.json` with a live pid and an answering `/api/v1/health` → `Installed PLIST → running, pid N, URL` (+ `cli::serve::print_credential_note` after a first run). `status` = one line from `server.json` — `running  pid N  since YYYY-MM-DD HH:MM (local)  URL  store DIR/store  log DIR/logs/server.log  (vX from health)` or `not running  store …  log …` — tab-separated non-TTY, two spaces TTY, plus a stderr note `LaunchAgent LABEL installed (PLIST)` / `no LaunchAgent installed — …`; `--json {state, pid, since (ISO seconds), url, port, store, log, plist, installed, loaded, label, version}` (`daemon::FIELDS`). `start` = bootstrap (+kickstart) then the status line; `stop` = bootout (plist stays; `start`/next login brings it back), idempotent; `restart` = `kickstart -k` (or bootstrap when unloaded), waits for a *new* pid; `uninstall` = bootout + remove plist → `PLIST  stopped and removed|removed|stopped|not installed  (data dir DIR kept)` (`UNINSTALL_FIELDS {plist, removed, stopped, label}`), idempotent. Upgrade = replace the binary at the plist's path, `daemon restart`. The label is fixed (`com.annotary.server`) — one daemon per user; `install` on an installed daemon re-installs.
- **Test seams (never set by users):** `ANNOTARY_DAEMON_OS` overrides the detected OS (`linux` ⇒ the exit-1 path on a Mac; `macos` ⇒ `status` runs anywhere — `is_loaded()` is false when `launchctl` is missing), `ANNOTARY_LAUNCHD_LABEL` overrides the label/plist name (the e2e harness sets `com.annotary.e2e`, `tests/cli_daemon.rs` a private one), `ANNOTARY_LAUNCHD_TESTS=1` enables the live launchctl round trip (`make launchd-test`), `ANNOTARY_HOUSEKEEPING_INTERVAL` (seconds) shortens the ticker. `HOME` decides where `Library/LaunchAgents` is — tests point it at a temp dir.
- **`export FILE.tar [--force]`:** `annotary_store::export_tar(store_dir, writer)` writes `store/meta.json`, `store/annotary.sqlite` (one `rusqlite::backup` `step(-1)` from a read-only connection = a consistent snapshot, server running or not; no LOCK taken) and `store/blobs/sha256/ab/<hash>` for every blob (sorted; `LOCK`, `-wal`/`-shm`, `.tmp` stay out); the snapshot comes first, so a push during the export is merely absent from it. CMD-9: a purge / GC / derived-blob cleanup between the snapshot and the copy (the server is another process) could remove a blob the snapshot references, so `export_tar` reads the snapshot's referenced set (`backup::snapshot_references` = `docs::referenced_hashes`) and returns `StoreError::ExportIncomplete {missing}` when any of them was not archived (the seam `export_tar_with(…, after_snapshot)` is how the test interleaves a purge); the CLI (`export::with_retries`) drops the temp file and retries on a fresh snapshot (`ATTEMPTS` = 3, a stderr note each), then exits 5 listing the missing hashes. The CLI writes a sibling `.FILE.pid.tmp` then renames, refuses an existing FILE without `--force` (5), a non-`.tar` name (1), no store (5); prints `FILE  N blobs  SIZE  schema vK` (`--json {file, blobs, bytes, size, schema_version, tenant_id, store, live}`) and a note when a server is running. Restore = untar into a fresh data dir and `serve --data-dir` there (no `import` verb).
- **Housekeeping:** `Store::auto_purge_days()` / `set_auto_purge_days(by, Option<u32>)` (settings key `auto_purge_days`; absent/`0` = off — the default; > `AUTO_PURGE_MAX_DAYS` ⇒ `Invalid` → 400; event `setting.auto_purge {days}`), `auto_purge_due(now)` / `auto_purge(now) -> Vec<PurgeOutcome>` (deleted ≥ N days before the injectable `now`, each through `purge_document_as(None, id)` ⇒ `document.purged {name, auto: true}` with `by: null`; a Document restored in between is skipped), `gc_sweep(grace) -> (removed, bytes)` behind `gc_blobs`, `clean_derived(is_stale, grace) -> DerivedCleanup {html_dropped, blobs_removed, bytes, temp_removed}` (Versions whose `html_hash` is set and `is_stale(renderer)` — the server passes `!annotary_renderer::is_current` — get `html_hash`/`renderer` NULL in one tx with one `housekeeping.cleaned {versions, html_blobs}` event; the blobs nothing references any more are removed; `BlobStore::sweep_temp(grace)` drops `.<hash>.<pid>.tmp` leftovers). A tick (`server::housekeeping::tick(store, now)`) = `auto_purge` → `gc_sweep(GC_GRACE = 1 h)` → `clean_derived` and logs `housekeeping: purged N Documents, GC removed K blobs (SIZE), cleaned M stale renders (B blobs, SIZE), T temp files (ms)` at `info` (`debug` when nothing happened); the first tick fires one interval after start. `POST /api/v1/docs/{id}/purge` runs `gc_sweep` right after the purge and reports `gc_removed` (the CLI's `N blobs removed` note stays the purge's own count). Nothing ever removes a blob `version_blob_refs` still lists — extend that function, never the GC, when a new kind of blob appears.
- **Snapshots (CMD-1):** `annotary_store::snapshots` (`take_snapshot(store_dir, dir, seq, now, keep)`, `list_snapshots`, `snapshot_name`/`parse_snapshot_name`, `SNAPSHOTS_DIR`) and `server/snapshots.rs` (`ticker`, `tick`, `DEFAULT_INTERVAL` = 15 min, `KEEP` = 4, `INTERVAL_ENV` = `ANNOTARY_SNAPSHOT_INTERVAL` seconds, a test seam). `server::run` spawns the ticker beside housekeeping's: a tick right after start, then every interval, on a blocking thread. A tick = `export_tar` of `store/` into `DATA_DIR/snapshots/annotary-YYYYMMDDTHHMMSSZ-sN.tar` (`N` = `last_seq()` read before the copy; written to `.….tar.tmp`, fsynced, renamed; folder `0700`, files `0600`), then all but the newest `KEEP` removed. When the newest snapshot's `N` equals the current `last_seq()`, nothing is written and only its mtime moves to now, so `deploy/healthcheck.sh`'s age check (warning over 1 h, critical over 24 h, playbook P5) means "the server last checked the store this long ago". Tests: the unit tests in `snapshots.rs`, `tests/snapshots_server.rs` (real binary, 1 s interval), `deploy/test_healthcheck.sh`.
- **Decisions to keep:** an export is complete or it fails — verify against the snapshot's references, never a cross-process lock or a GC grace for exports (CMD-9, `docs/decisions.md`); `stop` = bootout (the agent stays installed and comes back at login — that is the point of a LaunchAgent); `export` reads the store directly (a backup must not need a server) and takes no LOCK; derived-blob cleanup means *stale rendered HTML* (the read path re-renders it anyway) + temp files — image derivatives and current HTML are ordinary referenced blobs for the GC; auto-purge has no actor; no CLI verb for the setting (ticket 12's settings screen; the API is there).
