- **Files:** `crates/store/src/links.rs` (settings + pure helpers, shared by CLI and server), `crates/annotary/src/qr.rs`, `server/pairing.rs`, `cli/link.rs`, `cli/pair.rs`, `server/mod.rs` (`parse_bind_ex`, `bind(ip, port, allow_remote)`), `cli/serve.rs` (`--allow-remote`, `--url`, `--link-base`; `parse_url_flag` / `apply_url_flags`, `LOOPBACK_HINT`), `cli/daemon.rs` (`InstallArgs` / `Plist` `bind`, `allow_remote`, `url`, `link_base`), `client.rs` (`Api::doc_link` / `display_link`), `view.rs` (`origin_of`, `open_app_link`), `admin.rs` / `admin.js` (Pair a device). No migration.
- **Remote bind:** `serve --bind ADDR` takes any IP only with `--allow-remote` (else exit 1 before the store is touched, hint names the flag); a non-loopback bind logs one `WARN` (API reachable from the network; set a local password for web access). `daemon install --bind --allow-remote --url --link-base` pass through to the plist's `serve` arguments (`--allow-remote` is the one valueless plist argument). `url_for` names an unspecified bind by its loopback address (`server.json`, `health.url`). **Loopback trust is decided by the peer (`ConnectInfo`), never by the bind** — keep it that way; `TestServer::start_remote(ip)` binds anything for tests.
- **Links:** settings `public_url` / `link_base` (`Store::public_url` / `set_public_url(by, Option<&str>)`, same for `link_base`; events `setting.public_url|link_base {url}`, `by: null` from `serve`; unchanged ⇒ no event) set only by `serve --url/--link-base URL|none` (a later `serve` without them keeps them); `health` + `GET /api/v1/settings` carry both (null when unset). `doc_link(public_url, link_base, id, thread)` is the one link builder: none ⇒ `None`; public only ⇒ `{public}/d/{id}[#tN]`; both ⇒ `{link_base}/{host[:port]}/d/{id}[#tN]` only when the relay rule (port ⇒ `http://`, no port ⇒ `https://`) reconstructs the public URL, never for IPv6 — else the plain link. `link DOC [tN]` prints it (no public URL ⇒ the CLI's server URL + a stderr note, exit 0); `show` / `push` append it on a TTY (non-TTY unchanged); the web page selects `#tN` like `#cd-tN`.
- **Pairing:** `POST /api/v1/pairing {member?, name?}` → 201 `{pair_url, server, profile, member, token, token_id, name, qr_svg}` — a Token through `mint_token_expiring` (no expiry, default name `device`; rights as tokens: self any Member, another owner-only), 409 `no_public_url` (→ exit 5) before minting; `pair_url` = `annotary://pair?v=1&server=&token=&profile=` (`percent_encode`: only `A-Za-z0-9-._~` kept), `profile` = `handle@first-DNS-label` / `handle@ip`. `pair` prints header + QR (quadrant blocks, 2Ã2 modules a character, error correction L, a 2-module quiet zone, light modules drawn) + `profile …` + the URL on a TTY and `PAIR_URL MEMBER TOKEN_ID NAME` otherwise. The Members screen's **Pair a device** (active Members only) shows `.cd-paironce[data-handle]` (a `.cd-tokonce` variant: `.cd-qr svg`, the sentence, Copy link = the pair URL, Dismiss) in the re-drawn card; errors go to `.cd-memerr`.
- **Titles / X5:** `title` on `GET /api/v1/docs` rows (after the limit) and `GET /api/v1/docs/{id}` via `ui::title_for` (`resolve` does not compute it); the web list reads the row's `title`. The Document page header carries `<a id="cd-openapp" class="cd-chip cd-openapp" hidden>` with `annotary://open?server=<pct public URL, else http://{Host}>&doc=<id>`; `app.js` shows it for `iPhone|iPad` (or `Macintosh` + `maxTouchPoints > 1`) and keeps `&thread=tN` in step with the fragment; `.cd-openapp[hidden]{display:none}` must stay (`.cd-chip` sets `display`).
- **Tests:** `tests/ios_prereqs.rs`, `tests/server_bind.rs` (router-level peers via `tower::ServiceExt::oneshot` + `ConnectInfo`; a real LAN listener when the machine has one), the `access_api.rs` rows `POST pairing (own)` / `{member: other}` (they set a public URL first); e2e `99-ios/` runs on the second harness server, started with `--url http://pw-host.example.ts.net:7377 --link-base https://cd.example.dev`, as profile `ios` (added to `config.toml` right before `99-ios` only); Playwright `tests/web/ios.spec.ts` (an iPhone `userAgent`; the pairing success path on a private `spawnServer(undefined, ['--url', …])` — the shared server keeps no public URL).
- **Decisions to keep:** remote access is an explicit opt-in and never widens loopback trust; one `doc_link` for every printed link; pairing mints an ordinary, revocable Token (nothing pairing-specific in the store); the plain Token appears only in the pairing response / panel; the relay itself (and `apple-app-site-association`) lives outside this repo.
